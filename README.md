# Практическая работа 3.

Задание заключалось в описании структуры `Task` (идентификатор, название, статус и приоритет) и написании методов и функций для работы с ней. Методы `Summary`, `Complete` и `SetPriority` используют разные типы получателей: `Summary` работает со значением (`Task`), а `Complete` и `SetPriority` меняют задачу, поэтому принимают указатель (`*Task`). Метод `SetPriority` дополнительно проверяет, что приоритет находится в диапазоне от 1 до 3, и возвращает `false` при неверном значении. Функция `findTaskByID` возвращает указатель на найденную задачу или `nil`, а `tasksByStatus` возвращает новый срез задач с нужным статусом (последние две функции являются дополнительными).

**Запуск программы**

```text
go run ./cmd/task-manager
```

**Что делает программа**

1. Создаёт срез из трёх задач.
2. Находит задачу с `ID = 2`, завершает её и ставит приоритет `3`.
3. Выводит краткое описание всех задач.
4. Пытается найти задачу с несуществующим `ID = 99` и сообщает, что она не найдена.
5. Выбирает задачи со статусом `done` и выводит их.

**Результат**

```text
#1 Установить Go [done], приоритет 1
#2 Освоить функции [done], приоритет 3
#3 Изучить структуры [new], приоритет 3
Задача не найдена
#1 Установить Go [done], приоритет 1
#2 Освоить функции [done], приоритет 3
```

# Практическая работа 4.

Задание заключалось в написании консольного приложения для управления задачами с хранилищем в памяти. Поведение хранилища описано интерфейсом `TaskStore` (методы `Add`, `Get`, `Complete`, `Delete`, `List`), а его реализация `MemoryStore` хранит задачи в срезе и счётчик `nextID` для выдачи идентификаторов. Метод `Add` обрезает пробелы в названии и проверяет, что название не пустое, а приоритет находится в диапазоне от 1 до 3, при неверных данных возвращается `ErrInvalid`, а `nextID` не увеличивается. Методы `Get`, `Complete` и `Delete` ищут задачу по `ID` циклом, а не используют `ID` как индекс, потому что после удалений они перестают совпадать. Если задача не найдена, возвращается `ErrNotFound` (в `Get` он обёрнут через `%w`). Метод `List` возвращает копию среза, поэтому изменение результата не влияет на внутреннее состояние хранилища. Функция `run` принимает интерфейс `TaskStore`, а не конкретный тип, и при выходе из программы срабатывает `defer` (последние проверки с `errors.Is` и копией среза являются дополнительными).

**Запуск программы**

```text
go run ./cmd/task-store
```

**Команды меню**

| Команда | Действие |
|---:|---|
| `1` | Добавить задачу (название и приоритет 1–3) |
| `2` | Показать список задач |
| `3` | Завершить задачу по `ID` |
| `4` | Удалить задачу по `ID` |
| `0` | Выход |

**Обязательные проверки**

| Шаг | Действие | Результат |
|---:|---|---|
| 1 | Показать список сразу после запуска | Список пуст |
| 2 | Добавить `Изучить Go`, приоритет 2 | `ID = 1`, статус `new` |
| 3 | Добавить название из одних пробелов | «Неверные данные», `ID` не расходуется |
| 4 | Добавить приоритет 0 и 4 | «Неверные данные» |
| 5 | Добавить `Написать API`, приоритет 3 | `ID = 2` |
| 6 | Завершить `ID = 1` | Статус `done` |

**Дополнительные проверки**

Перед запуском меню в `main` выполняются две проверки на отдельном хранилище, чтобы они не влияли на `ID` в меню:

1. `errors.Is(err, ErrNotFound)` для результата `Get(999)`: ошибка распознаётся, несмотря на обёртку через `%w`.
2. Изменение элемента в срезе, который вернул `List()`, не меняет данные внутри `MemoryStore`.
